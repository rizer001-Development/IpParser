# IpParser

![Java](https://img.shields.io/badge/Java-8%2B-orange)
![Dependencies](https://img.shields.io/badge/dependencies-none-brightgreen)
![License](https://img.shields.io/badge/license-AGPL--3.0-blue)

> An open-source IP address parser for quickly and efficiently checking a huge number of IP addresses.

**IpParser** — портативный сканер IP-адресов и TCP-портов с графическим интерфейсом (Swing, тёмная тема). Программа разворачивает Java-регулярное выражение (или CIDR-блок) в список IPv4-адресов и проверяет, открыт ли на них указанный порт (или диапазон портов). Умеет пинговать Minecraft-серверы по официальному протоколу Server List Ping и показывать их MOTD, версию, онлайна и бренд.

Сотни миллионов адресов обрабатываются без зависаний: адреса генерируются «на лету» в фоновых потоках, а память остаётся постоянной благодаря ограниченным очередям.

---

## Возможности

- 🔢 **Гибкий синтаксис целей**: `ip`, `wildcard`, `regex` + поддержка **CIDR**-блоков прямо внутри выражения.
- 📋 **Три режима ввода**: одиночный паттерн, список паттернов, файл.
- 📊 **Живая шкала объёма** — сразу показывает примерное количество IP и оценку времени.
- 🌐 **Два режима сканирования**:
  - **Telnet (TCP port)** — классическая проверка открытых TCP-портов;
  - **Minecraft (mcprobe)** — Server List Ping: версия, MOTD, игроки онлайн/макс, иконка, бренд сервера, пинг.
- 🚪 **Один порт или диапазон** (`2000` или `2000-2010`).
- ✅ **Два статуса результата**: статус 1 — открыт/закрыт порт локально; статус 2 — доступен ли IP:порт извне (белый/серый IP, без внешних сервисов).
- ⚡ **Максимальная скорость**: три независимых пула потоков (генерация → сеть → парсинг), сетевых потоков — до **1024**.
- 🧠 **Ленивая генерация адресов** — даже `0.0.0.0/0` (весь IPv4, ~4,3 млрд адресов) не «вешает» интерфейс.
- 🛡 Подтверждение перед запуском при более чем **100 млн** целей.
- 📈 **Монитор процесса**: CPU, RAM (heap), входящий/исходящий трафик в реальном времени.
- 🔎 **Фильтры логов для Minecraft**-режима: онлайн, версия, бренд, MOTD, список игроков (операторы `is / above / below / in-range / out-of-range`).
- 📄 **Экспорт результатов** в `.txt`.
- 💾 Настройки автоматически сохраняются в `settings.txt`.
- 📦 **Без внешних библиотек** — только стандартная JDK.

## Требования

- **Java 8 или новее** (JRE достаточно для запуска, JDK нужен для сборки).
- Никаких внешних библиотек.

## Запуск (Windows)

Двойной клик по **`launch.bat`** — если классы уже скомпилированы, программа запустится сразу (через `javaw`, окно консоли мгновенно закрывается). При первом запуске `launch.bat` сам вызовет `build.bat`.

Двойной клик по **`launch.vbs`** — полностью скрытый запуск: окно консоли не появляется вообще.

## Сборка вручную

```bash
javac -encoding UTF-8 -cp . IpPattern.java PortScanner.java IpUtils.java McProbe.java McProbeScanner.java PerfMonitor.java IpParserGUI.java
```

Или просто запустите **`build.bat`**.

## Использование

### Синтаксис целей

Справа от поля «Syntax» кнопка **⚙** открывает окно «IP parsing settings»:

| Настройка | Варианты |
|---|---|
| **Type** | `ip` / `wildcard` / `regex` — как понимать текст в поле |
| **Input mode** | `single` / `list` / `file` — откуда брать паттерны |
| **Use CIDR** | `no` / `yes` — разрешать ли CIDR-блоки |

**Type `ip`** — полный IP-адрес: `95.31.158.9` (с CIDR: `95.31.158.9/24`).

**Type `wildcard`** — октеты со звёздочками, `*` = «любое число»:
- `95.31.***.*` → любые значения в 3-м и 4-м октетах;
- `95.31.1*0.1` → 100..190 в 3-м октете (шаг 10);
- с CIDR: `95.31.***.*/8` — звёздочки в базе становятся 0.

**Type `regex`** — обычный Java-regex по IPv4 (4 октета 0-255, разделённые точками). Якоря `^` и `$` в начале/конце необязательны, разделитель можно писать как `\.` или обычной точкой.

**Use CIDR** включает/выключает интерпретацию «адрес/префикс». При `CIDR=no` символ `/` в поле считается ошибкой.

### Режимы ввода

1. **Single** — одна строка (паттерн по выбранному типу).
2. **List** — несколько паттернов, по одному на строку; все результаты сканируются вместе:
   ```
   ^95\.31\.\d{1,3}\.\d$
   192\.168\.1\.\d
   10.0.0.0/8
   ```
3. **File** — файл в том же формате (по одному паттерну на строку); путь пишется в поле или выбирается кнопкой 📂. Файл перечитывается при старте скана.

Шкала справа суммирует количество IP по **всем** паттернам (List/File) с учётом типа и настройки CIDR.

### Примеры синтаксиса

| Выражение | Результат | Адресов |
|---|---|---|
| `^95\.31\.\d{1,3}\.\d$` | 95.31.0.0 … 95.31.255.9 | 2 560 |
| `^192\.168\.1\.\d$` | 192.168.1.0 … 192.168.1.9 | 10 |
| `172\.16\.1\d\d\.1` | 172.16.100.1 … 172.16.199.1 | 100 |
| <code>10\.0\.(?:[1-9]&#124;1[0-9])\.\d</code> | 10.0.1-19.0-9 | 190 |
| `192.168.1.0/24` | 192.168.1.0 … 192.168.1.255 | 256 |
| `95\.31\.0\.0/16` | 95.31.0.0 … 95.31.255.255 | 65 536 |
| `^10\.0\.0\.0/8$` | 10.0.0.0 … 10.255.255.255 | 16 777 216 |
| `0.0.0.0/0` | весь IPv4 | 4 294 967 296 |
| <code>95\.31\.0\.0/16&#124;10\.0\.0\.0/8</code> | оба блока сразу | ~16,8 млн |

Полезные конструкции regex: `\d` (одна цифра), `\d{1,3}` (октет 0-255), `[0-9]`/`[1-9]` (классы), `(?:a|b)` (варианты без захвата), `\d+` (повторения).

**CIDR**: префикс от 0 до 32, база не обязана быть выровненной (`192.168.1.5/24` → весь блок `192.168.1.0/24`). Ограничений нет — regex разворачивается в любое количество адресов, генерация идёт на лету.

**Шкала объёма** (обновляется при каждом нажатии клавиши):

| Объём | Оценка |
|---|---|
| 🟢 до 10 000 | Normal — quick scan |
| 🟢 10k – 100k | Normal — a minute or two |
| 🟡 100k – 1M | Elevated — may take several minutes |
| 🟠 1M – 10M | High — may take tens of minutes |
| 🔴 10M – 100M | Very high — may take hours |
| 🔴 больше 100M | Extreme — may take many hours |

### Порт

- Один порт: `2000`
- Диапазон: `2000-2010` (через **дефис**, без пробелов; программа сама отсортирует, если ввести `2010-2000`)

Порядок сканирования: сначала все порты первого IP, затем все порты второго и т.д. (IP за IP).

### Режимы сканирования (Mode)

1. **Telnet (TCP port)** — простая проверка открытости TCP-порта.
2. **Minecraft (mcprobe)** — пинг Minecraft-серверов по протоколу Server List Ping. В лог выводится версия, MOTD, игроки онлайн/макс, наличие иконки, пинг. Открытым считается сервер, ответивший корректным пакетом. Порт по умолчанию: **25565**. Диапазон портов тоже поддерживается.

### Два статуса результата

- **Статус 1 — ДОСТУП** (всегда): ✅ `OPEN` / ❌ `CLOSED` / ⏳ `TIMEOUT` / ❓ `ERROR`.
- **Статус 2 — ИЗВНЕ** (включается в настройках логов): доступен ли IP:порт из интернета. Всё определяется локально, без внешних сервисов:
  - 🌍 белый IP + открытый порт → доступен извне (проброшен);
  - 🌍 белый IP + закрытый порт → недоступен;
  - 🌍 серый IP (приватный) / адрес локальной сети → извне недоступен в принципе.

  *Примечание: гарантия не 100% (редкие исключения — фильтрация по источнику, hairpin NAT при проверке собственного белого IP).*

### Кнопки

| Кнопка | Действие |
|---|---|
| ▶ **Start** | начать сканирование |
| ■ **Stop** | остановить сканирование |
| 📄 **Export** | сохранить найденные открытые порты в `.txt` |
| **Clear log** | стереть окно логов |
| ⚙ **Settings** | настройки логов (шапка окна логов) |

### Настройки

- **Timeout (ms)** — время ожидания ответа порта (по умолчанию 1500).
- **Потоки**:
  - **Parse** — CPU-потоки обработки результатов (максимум = числу ядер);
  - **Gen** — CPU-потоки генерации адресов (максимум = числу ядер);
  - **Net** — **сетевые** потоки, открывающие соединения (до **1024**, не зависят от числа ядер).

Генерация, сеть и парсинг работают одновременно на максимальной скорости: генераторы раскидывают адреса по ограниченной очереди (блокировка только при полной очереди, без искусственных задержек).

### Фильтры логов (Minecraft-режим)

В окне «Log settings» помимо галочек (открытые/закрытые/таймауты/ошибки/действия/Status 2) есть MC-фильтры:

- ☐ Log if **online** — `is/above/below/in-range/out-of-range` (`5` или `10-30`);
- ☐ Log if **version** — то же (`1.21.1` или `1.21.1-1.21.4`);
- ☐ Log if **brand name contains** — Java regex (например `Leaf|Paper`);
- ☐ Log if **MOTD contains** — Java regex;
- ☐ Log if **player list contains** — Java regex.

Ответы, не прошедшие все включённые фильтры, не попадают ни в лог, ни в счётчики, ни в экспорт. Пустое значение = фильтр выключен.

### Монитор процесса

Внизу окна раз в секунду обновляется:
- **CPU** — загрузка процессора процессом Java (в %);
- **RAM** — используемая память JVM (использовано / всего heap, МБ);
- **IN / OUT** — входящий и исходящий сетевой трафик (скорость и всего). В Minecraft-режиме — реальные байты пинга, в Telnet-режиме — оценка TCP-рукопожатия.

## Как это устроено

Сканирование построено на **трёх независимых пулах потоков**, соединённых ограниченными очередями (по 8192 элемента):

```
[Генераторы (CPU)] → очередь задач → [Сетевые воркеры (до 1024)] → очередь результатов → [Парсеры (CPU)] → лог/счётчики
```

- **Генераторы** разворачивают regex/CIDR в пары `IP:порт` и кладут их в очередь (блокирующая `put` = естественное «обратное давление», без busy-wait и искусственных пауз).
- **Сетевые воркеры** открывают TCP-соединения (блокирующий I/O) — это не CPU-потоки, их число независимо и может достигать 1024.
- **Парсеры** обрабатывают результаты и зовут колбэки (подсчёт, статистика, лог).

Память остаётся **постоянной** (ограниченные очереди) независимо от размера диапазона, а UI никогда не блокируется: вся работа идёт в фоновых daemon-потоках.

|---|---|
