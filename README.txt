  IP Parser — портативный сканер IP-адресов и портов
═══════════════════════════════════════════════════════════════

ЧТО ЭТО
-------
Программа ищет все IP-адреса по Java-регулярному выражению (regex)
и проверяет, открыт ли на них указанный порт (или диапазон портов).
Результаты выводятся в окно логов в реальном времени и могут быть
экспортированы в файл .txt по кнопке.

СИНТАКСИС (IP PARSING SETTINGS)
--------------------------------
Справа от поля «Syntax» есть кнопка ⚙ (настройки). Она открывает окно
«IP parsing settings» с настройками:

   Type [ip / wildcard / regex]      — как понимать текст в поле
   Input mode [single / list / file] — откуда брать паттерны
   Use CIDR [no / yes]               — разрешать ли CIDR-блоки

ТИПЫ (Type)
-----------
   ip        — полный IP-адрес, например  95.31.158.9
               (с CIDR:  95.31.158.9/24)

   wildcard  — октеты со звёздочками; * означает «любое число»:
               95.31.***.*   → любые значения в 3-м и 4-м октетах
               95.31.1*0.1   → 100..190 в 3-м октете (шаг 10)
               (с CIDR:  95.31.***.*/8  — звёздочки в базе становятся 0)

   regex     — обычный Java-regex по IPv4 (4 октета 0-255, разделённые
               точками):  ^95\.31\.\d{1,3}\.\d$  |  95\.31\.0\.0/16

Use CIDR включает/выключает интерпретацию CIDR („адрес/префикс“).
При CIDR=no символ «/» в поле считается ошибкой.

РЕЖИМЫ ВВОДА (Input mode)
--------------------------
   1) Single — одна строка (паттерн по выбранному типу): Java-regex,
     описывающий IPv4-адреса: 4 октета (каждый 0-255), разделённые точками.
     Разделитель можно писать как \. или как обычную точку вне классов.
     Якоря ^ и $ в начале/конце — необязательны.

  2) List — несколько regex'ов / CIDR-блоков, по одному на строку:

        ^95\.31\.\d{1,3}\.\d$
        192\.168\.1\.\d
        10.0.0.0/8

     Каждая строка обрабатывается отдельно, все результаты сканируются
     вместе. Шкала справа показывает СУММУ IP-адресов всех строк.

  3) File — файл с таким же форматом, как режим List (по одному паттерну
     на строку). В поле пишется путь к файлу, либо нажимается значок
     папки 📂 и файл выбирается в диалоге. Файл перечитывается при
     старте скана и при изменении пути.

Шкала справа суммирует количество IP по ВСЕМ паттернам (List/File) с
учётом выбранного типа и настройки CIDR.

Примеры (Single, тип regex):

  ^95\.31\.\d{1,3}\.\d$        → 95.31.0.0 … 95.31.255.9      (2560 адресов)
  ^192\.168\.1\.\d$            → 192.168.1.0 … 192.168.1.9    (10 адресов)
  172\.16\.1\d\d\.1            → 172.16.100.1 … 172.16.199.1  (100 адресов)
  10\.0\.(?:[1-9]|1[0-9])\.\d  → 10.0.1-19.0-9                (190 адресов)
  51\.\d{1,2}\.\d{1,3}\.\d     → 51.0-99.0-255.0-9

  \d        — одна цифра (0-9)
  \d{1,3}   — от 1 до 3 цифр (целый октет 0-255)
  [0-9]     — класс символов (можно диапазоны: [1-9], [12])
  (?:a|b)   — варианты без захвата
  \d\d, \d+ — повторения

CIDR ВНУТРИ REGEX
-----------------
  CIDR — это не отдельный режим, а часть синтаксиса: блок записывается
  прямо в поле «Syntax» и работает как regex. Точки можно писать
  как \\. (regex-стиль) или обычные:

    192.168.1.0/24      → 192.168.1.0 … 192.168.1.255   (256 адресов)
    95\.31\.0\.0/16     → 95.31.0.0 … 95.31.255.255     (65536 адресов)
    95.31.0.0/16        → то же самое (обычные точки)
    ^10\.0\.0\.0/8$      → 10.0.0.0 … 10.255.255.255     (16 777 216)
    1.2.3.4/32          → один адрес 1.2.3.4
    0.0.0.0/0           → весь IPv4 (4 294 967 296 адресов)

  Несколько диапазонов можно объединить символом | (альтернация):

    95\.31\.0\.0/16|10\.0\.0\.0/8   → оба блока сразу (16,8 млн адресов)
    192\.168\.1\.0/24|192\.168\.2\.0/24 → два соседних блока

  Префикс — от 0 до 32. База не обязана быть выровненной
  (192.168.1.5/24 → всё равно весь блок 192.168.1.0/24).
  Для CIDR работает та же шкала, ленивая генерация адресов
  и подтверждение при очень большом объёме.

  Ограничений НЕТ: regex разворачивается в любое количество адресов.
  Адреса генерируются НА ЛЕТУ в фоновом потоке (без построения
  гигантского списка), поэтому даже сотни миллионов адресов не
  замораживают интерфейс. Шкала покрывает весь диапазон вплоть до
  миллиардов адресов (последняя ступень — Massive).

  Рядом с полем «Syntax» есть живая шкала (gauge) — при вводе она
  показывает объём цветом и подсказкой (на английском):

    🟢 до 10 000      — Normal — quick scan
    🟢 10k – 100k     — Normal — a minute or two
    🟡 100k – 1M      — Elevated — may take several minutes
    🟠 1M – 10M       — High — may take tens of minutes
    🔴 10M – 100M     — Very high — may take hours
    🔴 больше 100M    — Extreme — may take many hours

  Шкала обновляется при каждом нажатии клавиши. При большом объёме
  целей (более 100 млн) перед стартом появится окно подтверждения —
  это не ограничение, а лишь предупреждение о долгом сканировании.

ПОРТ
----
  Один порт:        2000
  Диапазон портов:  2000-2010   (все порты между ними включительно)

  Внимание: диапазон указывается ЧЕРЕЗ ДЕФИС в одном поле, без пробелов.
  Программа сама отсортирует порты, если ввести 2010-2000.

  Порядок сканирования: сначала проверяются ВСЕ порты первого IP,
  затем ВСЕ порты второго IP и так далее (IP за IP, а не порт за портом).

РЕЖИМЫ ПАРСИНГА
---------------
  В окне настроек есть поле «Mode»:

  1) Telnet (TCP port) — простая проверка: открыт ли TCP-порт.
  2) Minecraft (mcprobe) — пинг Minecraft-серверов по официальному
     протоколу Server List Ping. Показывает в логе: версию, MOTD
     (сообщение сервера), игроков онлайн/макс, наличие иконки, пинг.
     Открытым считается сервер, который ответил корректным пакетом.
     Порт по умолчанию для Minecraft: 25565.

  Для Minecraft-режима также можно указывать диапазон портов —
  все порты каждого IP будут проверены по очереди.

ДВА СТАТУСА РЕЗУЛЬТАТА
----------------------
  Статус 1 — ДОСТУП (всегда): открыт ли порт на IP (локальная TCP-проверка).
     ✅ OPEN / ❌ CLOSED / ⏳ TIMEOUT / ❓ ERROR

  Статус 2 — ИЗВНЕ (включается галочкой «Status 2: port reachable from
  outside (port forwarding / public IP)»): доступен ли IP:порт из интернета.
     🌍 EXTERNAL: public IP — port reachable from outside (forwarded)  — зелёный
     🌍 EXTERNAL: public IP — port closed, not reachable from outside — красный
     🌍 EXTERNAL: private IP — not reachable from outside             — серый
     🌍 EXTERNAL: LAN address — not reachable from outside            — серый

  Как это работает: если IP белый (публичный), то TCP-коннект из вашей
  сети уже идёт через интернет, поэтому открытый порт на белом IP
  фактически означает доступность снаружи. Серые IP (10.x, 172.16-31.x,
  192.168.x, 100.64/10 CGNAT, 127.x, 169.254.x и др.) и адреса вашей
  локальной сети извне недоступны в принципе. Всё определяется локально,
  без внешних сервисов.

  Примечание: гарантия не 100% (редкие исключения — фильтрация по
  источнику на сервере, hairpin NAT на вашем роутере при проверке
  собственного белого IP).

КНОПКИ
------
  ▶ Start    — начать сканирование
  ■ Stop     — остановить сканирование
  📄 Export  — сохранить найденные открытые порты в .txt файл
  Clear log  — стереть окно логов
  ⚙ Settings — настройки логов (возле окна логов, справа)

НАСТРОЙКИ ЛОГОВ (кнопка ⚙ Settings)
------------------------------------
  Диалог открывается кнопкой ⚙ Settings в шапке окна логов.
  Содержит две секции:

  Logs settings (что писать в лог):
    ☑ Log available IP/Port connections   — открытые (доступные)
    ☐ Log closed IP/Port connections      — закрытые
    ☐ Log timed out IP/Port connections   — таймауты
    ☐ Log errored IP/Port connections     — ошибки
    ☑ Log actions (e.g. change IP regex)  — служебные строки
       (SCANNING STARTED / FINISHED, stop, export)
    ☐ Status 2: port reachable from outside — второй статус
       (публичный IP + открытый порт = доступен извне)   MC-probe log filter (только Minecraft-режим):
     ☐ Log if online          [is/above/below/in-range/out-of-range] [5  или  10-30]
     ☐ Log if version         [is/above/below/in-range/out-of-range] [1.21.1  или  1.21.1-1.21.4]
     ☐ Log if brand name contains    [java regex, например Leaf|Paper]
     ☐ Log if MOTD contains          [java regex]
     ☐ Log if player list contains   [java regex]

     out-of-range = вне указанного значения/диапазона (для одного значения
     это «не равно», для диапазона «1.21.1-1.21.4» — «вне этих версий»).
     Бренд, MOTD и список игроков фильтруются Java-regex (для
     регистронезависимого поиска добавьте (?i)).

  В MC-режиме успешные ответы, не прошедшие ВСЕ включённые фильтры,
  не попадают ни в лог, ни в счётчики, ни в экспорт. Пустое значение
  у фильтра = фильтр выключен.

  Старые галочки «Show only open ports» и «Status 2» с главного окна
  перенесены сюда (эквиваленты — «Log available...» и «Status 2»).

НАСТРОЙКИ
---------
  Timeout (ms) — время ожидания ответа от порта (по умолчанию 1500).

  Threads — три отдельных поля:
    Parse: сколько ЦП-потоков обрабатывают результаты (максимум = числу ядер
           процессора, парсер использует их на максимум).
    Gen:   сколько ЦП-потоков генерируют IP-адреса из regex/CIDR
           (максимум = числу ядер процессора).
    Net:   сколько СЕТЕВЫХ потоков открывают соединения (до 1024).
           Это отдельная категория: сетевые потоки не относятся к ЦП-потокам
           и могут работать в количестве до 1024 независимо от числа ядер.

  Генерация, сеть и парсинг работают ОДНОВРЕМЕННО на максимальной скорости:
  генераторы раскидывают адреса по ограниченной очереди (блокировка только
  при полной очереди, без искусственных задержек), сетевые потоки открывают
  соединения сразу, как только появляются адреса, а ЦП-парсеры обрабатывают
  результаты. Если генерация медленнее парсинга — потоки просто ждут
  следующего адреса и продолжают мгновенно.

  Маркер на шкалах (IP-количество и сетевые потоки) — тонкая чёрная
  вертикальная линия на позиции текущего значения.


МОНИТОР ПРОЦЕССА
-----------------
  Внизу окна в реальном времени (раз в секунду) отображается:
    CPU — загрузка процессора процессом Java (в %)
    RAM — используемая память JVM (использовано / всего heap, в МБ)
    IN / OUT — входящий и исходящий сетевой трафик (скорость и всего)

  Счётчики трафика считаются на уровне сокетов: в Minecraft-режиме —
  реальные байты пинга, в Telnet-режиме — TCP-рукопожатие соединения.

ЗАПУСК
------
  Двойной клик по launch.bat  — если классы уже скомпилированы,
  программа запустится сразу. Запуск идёт через javaw, поэтому
  окно консоли мгновенно закрывается и не висит во время работы.

  Двойной клик по launch.vbs  — полностью скрытый запуск: окно
  консоли не появляется вообще (launch.vbs сам вызывает launch.bat).

  Если запуск первый раз, launch.bat сам вызовет build.bat.

ЛОГИРОВАНИЕ
-----------
  Окно логов НЕ очищается автоматически при старте/стопе сканирования
  или экспорте — все предыдущие результаты остаются на месте.
  Очистить лог можно только кнопкой «Clear log».

СБОРКА ВРУЧНУЮ
--------------
  javac -encoding UTF-8 -cp . IpPattern.java PortScanner.java IpUtils.java McProbe.java McProbeScanner.java PerfMonitor.java IpParserGUI.java

ТРЕБОВАНИЯ
----------
  Java 8 или новее (JRE достаточно для запуска, JDK нужен для сборки).
  Никаких внешних библиотек — только стандартная JDK.

ФАЙЛЫ
-----
  IpPattern.java     — разбор Java-regex в список IPv4-адресов
  PortScanner.java   — многопоточный сканер TCP-портов (Telnet-режим)
  McProbe.java       — пинг Minecraft-серверов (Server List Ping)
  McProbeScanner.java— многопоточный сканер MC-серверов (mcprobe-режим)
  IpUtils.java       — определение белый/серый IP и локальной сети
  PerfMonitor.java    — монитор CPU / RAM / сетевого трафика процесса
  IpParserGUI.java   — графический интерфейс (Swing)
  build.bat          — компиляция
  launch.bat         — запуск
  launch.vbs         — скрытый запуск без окна консоли
  settings.txt       — последние настройки (создаётся автоматически)
